# 系统配置页改版部署说明

本文给出「管理设置 → 系统配置」页改版（左侧锚点导航重排 + 右上角 toast 提示）上线时，服务器需要重新执行的完整命令。

## 0. 变更范围与影响

| 项目 | 说明 |
| --- | --- |
| 改动文件 | `web/src/views/Settings.vue`、`web/src/views/Admin.vue`、`web/src/App.vue`，新增 `web/src/toast.js`、`web/src/components/ToastHost.vue` |
| 交付形态 | 纯前端改动，构建后内嵌进 Go 二进制，服务器不需要 Node.js |
| 数据库 | **无 schema 迁移**，数据库、WAL/SHM 不受影响 |
| 配置项 | 无新增或变更；SMTP、模型密钥等设置保持原样 |
| 部署方式 | 适用于按 [deployment-2c4g.md](deployment-2c4g.md) 部署、由 systemd 管理 `gk` 的服务器 |
| 登录态 | 数据库不变，已有管理员会话继续有效 |

## 1. 命令速览

以下命令按顺序执行即可；变量替换为你自己的值。

```bash
# 服务器地址
SERVER_IP=你的服务器公网IP
SSH_USER=ubuntu          # 以腾讯云实例连接页为准，Ubuntu 镜像通常为 ubuntu

# ---------- 本地执行 ----------
git pull
make release
scp var/gk-linux-amd64.tar.gz ${SSH_USER}@${SERVER_IP}:/tmp/

# ---------- 服务器执行（SSH 登录后） ----------
sudo systemctl start gk-backup.service          # 先做一致性备份
sudo systemctl stop gk                          # 停服务
sudo cp /opt/gk/gk /opt/gk/var/gk.previous      # 保留旧程序，供回滚
sudo tar -xzf /tmp/gk-linux-amd64.tar.gz -C /opt/gk
sudo chmod 755 /opt/gk/gk
sudo systemctl start gk                         # 启服务
curl --fail http://127.0.0.1:8080/healthz       # 期望 {"ok":true}
```

## 2. 本地：构建发布包

在项目根目录执行：

```bash
git pull
git log -1 --oneline        # 确认包含本次提交
make release
```

`make release` 会先构建前端，再交叉编译 Linux amd64 二进制，最后打包。产物：

```text
var/gk-linux-amd64.tar.gz
```

本地核验（建议记录 sha256，便于与服务器比对）：

```bash
ls -lh var/gk-linux-amd64.tar.gz
sha256sum var/gk-linux-amd64.tar.gz
tar -tzf var/gk-linux-amd64.tar.gz | head -12
```

压缩包约 12 MB，至少包含 `gk`、`deploy/`、`taxonomy/`、`docs/` 与 README；**不包含**数据库、密钥和题目图片。这些线上数据继续沿用，升级时不要覆盖。

## 3. 本地：上传到服务器

```bash
scp var/gk-linux-amd64.tar.gz ${SSH_USER}@${SERVER_IP}:/tmp/
```

SSH 非 22 端口时使用 `scp -P 端口`、`ssh -p 端口`。Windows 可用 WinSCP 或 Windows OpenSSH。

## 4. 服务器：先备份，再替换程序

SSH 登录服务器后依次执行。

### 4.1 触发一致性备份

```bash
sudo systemctl start gk-backup.service
sudo systemctl status gk-backup.service --no-pager
ls -lt /opt/gk/var/backups | head -5
```

备份目录形如 `/opt/gk/var/backups/20261020T055400Z/`，包含 `gk.sqlite`、匹配的 `secret.key` 和 `complete.json`。**只有带 `complete.json` 的目录才可用于恢复。** 如需额外确认：

```bash
sudo -u gk /opt/gk/gk backup --verify-bundle /opt/gk/var/backups/<备份目录名>
```

本次改动没有数据库迁移，备份主要用于兜底，恢复时可原样保留。

### 4.2 停止服务并保留旧程序

```bash
sudo systemctl stop gk
sudo cp /opt/gk/gk /opt/gk/var/gk.previous
sudo chmod 755 /opt/gk/var/gk.previous
```

### 4.3 解压新包

```bash
sudo tar -xzf /tmp/gk-linux-amd64.tar.gz -C /opt/gk
sudo chmod 755 /opt/gk/gk
```

解压只覆盖程序、部署模板、taxonomy 与文档，**不会**触碰以下线上数据：

```text
/opt/gk/var/db/gk.sqlite     数据库（含 WAL/SHM）
/opt/gk/var/secret.key       密钥
/opt/gk/data/90-图片/        题目图片
/opt/gk/var/gk.env           可选环境密钥（如存在）
```

不要为了“干净部署”删除 `/opt/gk/var` 或 `/opt/gk/data`，那会丢用户、练习记录和标注。

### 4.4 启动服务

```bash
sudo systemctl start gk
sudo systemctl status gk --no-pager
curl --fail http://127.0.0.1:8080/healthz
sudo ss -lntp | grep ':8080'
```

预期：

- 状态为 `active (running)`；
- `/healthz` 返回 `{"ok":true}`；
- 监听地址为 `127.0.0.1:8080`（只回环，由宝塔 Nginx 反向代理）。

## 5. 浏览器验收

打开线上站点，**强制刷新一次**（`Ctrl+Shift+R`，macOS 为 `Cmd+Shift+R`）。`index.html` 本身是 `no-cache`，带哈希的静态资源可长缓存，正常刷新通常也能拿到新页面；若仍是旧界面，先确认二进制已替换（见 §7）。

管理员登录 `/admin/login`，进入「系统配置」页，逐项检查：

1. 页面顶部首次进入时，右上角弹出蓝色提示「本阶段完成网站开发与部署准备……」，数秒后自动消失；
2. 左侧出现五个分区导航：LLM 接口、邮件服务、用户额度、成本与预算、参考约定；点击可平滑跳转，滚动时高亮跟随，滚动到底部高亮「参考约定」；
3. 各分区保存后，右上角弹出绿色「已保存」提示，约 4 秒自动消失；
4. 「测试连接」成功后弹出绿色提示，显示耗时与模型名；失败时弹出红色提示，**不会自动消失**，需点 × 关闭；
5. 「参考约定」下两张表收在折叠面板中，点击可展开；
6. 缩小窗口到 960px 以下，导航变为水平滚动条；640px 以下表单变单列。

仅本次页面改动相关，无需重新配置 SMTP 或模型密钥。

## 6. 回滚

本次发布**没有数据库迁移**，回滚只需换回旧二进制：

```bash
sudo systemctl stop gk
sudo cp /opt/gk/var/gk.previous /opt/gk/gk
sudo chmod 755 /opt/gk/gk
sudo systemctl start gk
curl --fail http://127.0.0.1:8080/healthz
```

数据库、密钥和图片保持不变。浏览器再次强制刷新即可看到旧界面。

> 若以后的版本包含 schema 迁移，回滚必须同时恢复升级前的 SQLite 快照与匹配密钥，不能只换回旧程序。参见 [deployment-2c4g.md §12.3](deployment-2c4g.md)。

## 7. 常见问题

| 现象 | 排查 |
| --- | --- |
| 服务起不来 | `sudo journalctl -u gk -n 100 --no-pager`；常见原因是磁盘空间、`/opt/gk/var` 权限或二进制不可执行 |
| 页面仍是旧版 | 对比服务器 `/opt/gk/gk` 与本地包的 sha256；确认解压的是新包；再强制刷新浏览器 |
| 保存返回 403 | 非 GET 请求有同源校验：确认通过 HTTPS 域名访问、Nginx 正确透传 Host/Origin，不要用 IP 直连绕过代理 |
| 保存后提示消失太快 | 成功类提示 4 秒自动关闭；错误与警告类常驻，点击 × 关闭 |
| 健康检查失败 | 确认端口为 `127.0.0.1:8080`，且服务在运行；`sudo ss -lntp \| grep ':8080'` |

## 8. 附录：Docker 路线

若服务器按 [部署方案 §5](部署方案.md) 使用 Docker Compose 而不是 systemd，在包含 `docker-compose.yml` 与 `.env` 的目录执行：

```bash
git pull

# 先给当前镜像打回滚标签（默认镜像名 practice-gk，自定义 IMAGE_NAME 时相应替换）
docker tag practice-gk:latest practice-gk:previous

docker compose run --rm backup      # 一致性备份，写入 ./var/backups/
docker compose build                # 重建镜像，新前端内嵌其中
docker compose up -d                # 用新镜像替换容器
curl -f http://127.0.0.1:8080/healthz
```

数据卷 `./var`（数据库、密钥、备份）与 `./var/data`（图片）不随镜像重建变化，无需重新上传。

回滚：

```bash
IMAGE_TAG=previous docker compose up -d
curl -f http://127.0.0.1:8080/healthz
```
