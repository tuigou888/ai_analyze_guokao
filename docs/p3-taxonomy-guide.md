> 规范表位置：`taxonomy/v1/taxonomy.yaml`（v1.5）

> 测试：`TestShippedTaxonomyIsSelfConsistent`、`TestTaxonomyNoDuplicateSecondary`

---

## 设计原则

### 1. 槽位即缓存

> 把槽位做粗能让 1:1 率变漂亮（一个筐吃下所有题），但那是假数字。

**实测证据**：v1.3 只补了「重要论述与讲话精神」一个宽槽位，27 道新思想题全落进去，27:1 收敛度漂亮但领域横跨外交/党史/文化/治疆/十五五/乡村振兴/粮食安全。v1.4 改成形态+领域双维度后散到 11 个考点。

**判定槽位粒度的唯一方法**：抽样查看槽位内的题是否真属同类。如果一个槽位里有 27 道题但领域完全不同，说明做成了筐。

### 2. 边界必须写死

模型在边界上摇摆，除非边界是显式可机械判定的。参考文档 §5 坑 5 的实测结论。

v1.5 的 10 条边界规则中，有 4 条是历次实测逼出来的：

| 规则 | 实测来源 |
|---|---|
| 逻辑填空按**选项形态**定考点（不看空格数） | 3 道里 1 道把全成语题标成实词辨析 |
| 现代制度→法律常识 / 古代制度→人文常识 | 公务员制度被标进人文常识（源标签误导） |
| 新思想三步判据（形态→领域） | 过度矫正后重新校准 |
| **讲话**：思想提法→新思想 / 时政事实→时事政治 | 两个「重要讲话」槽位打架 |

### 3. 修订先查数据再动手

每条修订都写明实测题量。中途查过「古代制度」类只有 3 题，于是**决定不给它加分档**——凭「应该有个地方放」的直觉扩展会把分档做虚、让 1:1 率反而变差。

## 边界规则（10 条）

1. 给词或成语填空属「逻辑填空」；给整句填空属「语句表达」
2. 逻辑填空按**选项形态**定考点（不看空格数）
3. 问「这段文字意在说明/主要观点」属「片段阅读-中心理解」；问「与原文相符/不符」属「细节判断」
4. 题干给出材料数据求某个量属「资料分析」；题干无材料、纯文字表述数量关系属「数量关系」
5. 「综合分析」只在同一道题需要跨两个及以上考点的判断时使用，不得当作兜底
6. 新思想三步判据：①文献原文→`重要文献与讲话原文` ②整体定位→`理论定位与核心内容` ③具体领域→对应领域
7. 讲话按考什么分（思想提法 vs 时政事实），不按讲话本身分
8. 党章与党的组织制度→「党章党规」，不要放进「新思想」
9. 常识判断制度类按时代分：现代制度→「法律常识」；古代制度→「人文常识-历史事件」
10. 逻辑填空与片段阅读的考点名**不得同义换写**

## 扩展口

若确属规范表覆盖不到的新考法，可新增三级考点，但必须：
- 带「大类-」前缀且前缀等于二级题型名
- 与已有考点**不重叠**（不是同义词换写）

实测长尾约 0.9%，审查后全是真实新考法，不是噪声。

新增后必须：
1. 跑 `go test ./internal/distill/ -run Taxonomy`（确保自洽）
2. 改 `version:` 号
3. 在文件头注释里写明**实测依据**（题量/命中数），便于日后回溯为什么这样分
4. 用同一批题回跑验证（换新 run_id），对比 1:1 率与新增考点数

## 解析契约

规范表必须通过它自己的校验器：

```go
func TestShippedTaxonomyIsSelfConsistent(t *testing.T) {
    for _, m := range tax.Modules {
        for _, s := range m.Secondary {
            for _, ter := range s.Tertiary {
                ok, _, reason := tax.ValidateTertiary(m.Subject, s.Name, ter)
                if !ok {
                    t.Errorf("规范表自相矛盾：%s / %s / %s —— %s", ...)
                }
            }
        }
    }
}
```

**来历**：v1.2 之前，常识判断与政治理论下的三级考点前缀写短了（`人文-`、`马原-`、`时政-`），而二级题型名是 `人文常识`、`马克思主义基本原理`、`时事政治`。于是校验器拒绝了规范表**自己列出的**考点，50 题 MVP 里白烧了 4 次 API 调用——在限流端点上这是双重浪费。这个错误人工看很难发现（两边看着都对），机器一跑就露。

## 快速操作

```bash
# 预览将发给模型的提示词（含完整规范表）
gk distill prompt --subject 资料分析

# 校验规范表自洽性
go test ./internal/distill/ -run Taxonomy

# 查看某批次的规范表版本与质检指标
gk distill report --run verify-500
```
