## 0. 任务身份与最终目标

你现在同时担任**资深产品设计师（B 端 / 教育产品）、UX 设计师、前端架构师与代码实施工程师**。请直接在当前代码仓库内完成「行测研习」全站 UI/UX 重构，不要停留于写建议；在保证现有业务与数据完全兼容的前提下，使网站成为统一、专业、轻量的**教育 SaaS 学习工作台**。

目标不是另起一个 UI demo，不是仅修改配色，也不是通过大量卡片、渐变、动画掩盖布局问题，而是**实际落地页面布局重构、设计系统统一、组件复用、交互增强与响应式适配**。

**验收优先级：功能正确 > 信息可读、任务效率与可访问性 > 响应式 > 视觉精致度 > 动效**。

1. **仅改动前端必要文件**：现有题库、试卷、考点、错题、收藏、练习记录、用户中心、管理设置等业务逻辑必须保留；不能随意改变数据库结构、API URL、响应字段、身份验证方式、Cookie、权限语义、模型配置或真实统计口径。
2. **先阅读仓库再实施**：自行识别框架（React / Vue / Next / Nuxt / 原生页面等）、路由、组件库、样式方案、构建工具与测试体系。**禁止假定已有 React、Tailwind 或 shadcn/ui**；优先沿用现有技术栈，不为视觉改版引入大型依赖。
3. **先识别旧页面对应代码**：梳理路由及相关组件文件，不要杜撰文件名、数据库字段或状态值。原始功能无法从代码查明时，保留旧行为并记录待确认，不做猜测性业务更改。

5. **已有登录和管理员功能必须保留**。绝不写入、传送、输出或硬编码真实 Cookie、API Key、管理员会话、密码或其他密钥；日志和截图中隐藏敏感内容。
6. **禁止视觉重构造成业务回退**：筛选、分页、开始练习、继续练习、提交、判题、查看解析、收藏、错题标记、用户管理、保存设置、测试连接等原功能全部保留并回归测试。
7. **保留中文为主的产品语言**。“行测研习”的品牌名称保留。减少无实用价值的英文装饰性副标题；保留必要的题型、地区和来源标签。
8. **参考样例不是可直接替换生产数据的功能代码**。`行测研习-页面布局参考.html` 为无后端的视觉 / 布局示例，须将其模式映射到现有框架与真实组件。
9. 使用渐进式改造，分阶段提交或至少保留清晰的改动边界；**不要删掉可用逻辑后用模拟数据代替**。
10. 首先完成静态代码审查，无需用户重复描述项目；能自动完成的测试和改动应直接执行。

## 1. 设计定位

关键词：**学习工作台 / 清爽蓝白 / 信息优先 / 克制 / 数据清晰 / 高密度但不拥挤 / 考试专注体验**。

主要参考：
- Ant Design：布局、列表、表格、表单的结构和视觉层级。https://ant.design/components/layout/ 与 https://ant.design/components/table/ 与 https://ant.design/components/form/
- shadcn/ui：可折叠侧栏、卡片、Tabs、Popover、DropdownMenu、Combobox 的交互结构（只参考设计模式，不要求迁移框架）。https://ui.shadcn.com/docs/components/base/sidebar 与 https://ui.shadcn.com/docs/components/base/combobox
- USWDS Combo box：当选项很长时使用输入可搜索的组合选择器。https://designsystem.digital.gov/components/combo-box/

注意：**不要 1:1 复制第三方产品，也不要引入第三方品牌标识。以原网站功能和本文件为设计权威。**

### 3.2 布局与尺寸

- 桌面全站外壳：左侧 224px 可折叠导航（折叠 64px），右侧主区；顶部标题栏高 64px；主区背景淡灰蓝。
- 正常列表页：内容 max-width 1360px，自适应居中，左右 padding 32px，垂直主间距 24px；页面大标题 26–28px，说明 14px；避免重复显示三层页面标题。
- 设置/表单页：表单优先 640–960px，字段有合理的最长宽度，不要单个文本框横跨 1300px。
- 阅读/答题页：主要阅读列 760–880px，右侧附属答题卡按已有功能展示；答题列在移动端单列。
- 卡片：圆角 12–14px、1px 淡边框、微弱或无阴影；内部 padding 20–24px。
- 表单：输入高 40–44px，label 和输入间距 6–8px，行间距 16–20px；主要按钮高度 40–44px。
- 基础排版：中文系统无衬线（优先已有字体栈），正文 14–16px，标签 12–13px，行高 1.55–1.7；数字使用 tabular-nums。
- 标准 8px 间距节奏；细节可 4px 倍数；避免同类元素横向/纵向节奏不一致。
- 不引入艳丽彩虹配色、玻璃态、拟物阴影、满屏渐变、大面积强调色及大量装饰图标。

### 3.3 公共组件

每个组件必须支持：默认态、hover、focus-visible、disabled、loading（按需）、error（按需）；对焦点有明显视觉反馈，交互元素使用真实 button / link 语义。图标来自项目已有图标库，不要额外引入三套图标系统。支持键盘操作、Esc 关闭浮层、弹层焦点管理。

## 4. 公共外壳及导航

- 保留原站 logo / “行测研习”。可折叠侧栏；分成“学习中心”和“复习与记录”两个主组。
- 学习中心：题库练习、真题试卷、考点地图。复习与记录：错题本、我的收藏、学习记录。底部：个人中心；有管理权限时才出现管理后台。
- 当前路由仅一项主菜单高亮，hover 不得误呈现第二个激活项；折叠状态显示 tooltip。侧栏可滚动，底部用户入口固定/稳定。
- 顶栏应简洁：页面名 / 简短面包屑在左，用户操作在右。会员信息可压缩为小 badge，不需要大面积头部横幅。
- 在产品子页面不重复用“顶栏页面名 + 英文标签 + 长句式大标题”三套标题；除个人中心欢迎页外，各页只保留一层主标题和一行必要描述。
- 页面滚动以主内容为主，避免全站容器出现意外的双重纵向滚动条。

## 5. 逐页面布局与交互要求

### 5.1 题库练习（截图：题库列表 27,449 题）

**目标：优先让用户找到题与开始练习，而不是让长筛选栏占据首屏。**

- 页头左侧“题库练习”+ 动态题量；右侧“开始专项练习”或保留现有实际命名。
- 首级筛选：关键词搜索、模块、查询按钮，以及高级筛选开关。展开后放年份、地区、考试类型、卷别（按现有实际数据字段提供）。
- 已生效筛选用 chip 展示，支持单独清除和清空；“选择条件”与“条件已应用”要有明确区分；维持已有查询触发语义。
- 列表每行：左上标签（模块/题型/ID），主区域 2–3 行题干，必要元信息，右侧唯一主要操作。行高随真实题干动态变化，不截断关键题意而没有可展开/详情途径。
- 批量练习数量可保留，但必须清楚显示“本次题量”与筛选范围；不改变实际随机/顺序抽题规则。
- 页码、页大小、筛选、返回后的滚动恢复要符合现有行为；避免自动全量加载上万题。
- 加载、无结果、失败状态均有设计，错误时可重试。

### 5.2 真题试卷（截图：2026 云南/上海/内蒙古等）

- 筛选按模块、年份、地区、考试类型、卷别分维度，避免把“选调”“深圳市考”等类别当成普通省份。
- 地区选择器采用可搜索 Combobox / 选择面板；支持输入汉字，数据允许时支持拼音；不重写后台枚举，仅在前端构造规范化选项及映射。键盘上下与 Enter 可用。
- 试卷卡片保留桌面三列，宽度不足时降两列/一列；卡片高度建议 210–250px。年份小标签+地区+标题+来源形式+题数+主按钮，题型等细节按真实数据展示；不要虚构答题时长、难度或进度。
- 标题最长三行、卡片底部 CTA 对齐；已进行中的试卷根据真实记录展示“继续作答”，已完成试卷按真实功能展示结果入口。
- 卡片 hover 轻微边框变化，无需上浮大动画。筛选结果与分页保持一致。

### 5.3 考点地图（截图：107 个已归纳考点）

- 桌面采用左侧知识分类树（240–300px）、右侧考点内容区域的双栏布局。移动端改分类下拉/抽屉。
- 左边树按现有模块 -> 子模块 -> 考点关系展示；右边显示选中的分类、考点列表及真实关联真题数；可按关键词搜索。
- 如果现有考点具有说明或解法，则在详情展示；没有的数据不得伪造。不能凭空生成“掌握度”“正确率”。
- 当前“仅展示已有标注覆盖考点”的提示改为简明局部说明，不要占据过大横幅。
- 选择考点后，保留跳转或联动到相关真题的既有行为；URL/选中状态尽量支持返回后恢复。

### 5.4 错题本（截图：待订正 4）

- 页头展示待订正数；顶部 segmented tabs：待订正 / 已订正 / 全部；保留原有状态判定。
- 题目行显示分类、题型、ID、答错次数、状态、题干摘要；保持题干可读。
- 原右侧纵向四按钮改为：一个主要按钮“重新练习”+ 次要收藏按钮 + “更多”操作菜单。更多包括按已有逻辑“标记已订正/取消订正”“移除”等。
- 危险操作“移除”必须二次确认或提供可撤销通知；不得误删原始作答记录或改变错误数据含义。
- 已订正后即时反馈状态与数量变化，使用真实 API，正确处理请求失败回滚。

### 5.5 我的收藏（截图：收藏 2 题）

- 复用 QuestionRow / 列表通用组件；收藏日期、标签与题干优先级清晰。
- 主要操作为开始练习 / 查看题目；取消收藏放次级操作并按既有逻辑确认或撤销。
- 单页数据时不展示无意义的禁用分页按钮；长题文支持合理换行。
- 不合并收藏和错题的数据库逻辑，它们只是复用 UI 组件。

### 5.6 学习记录（截图：累计作答8、正确率25%、待订正4、收藏2、完成练习1）

- 修复截图中“4 张卡片排一行，第 5 张独占下一行”造成的布局失衡。
- 首屏使用 4 项高价值指标（累计作答、正确率、待订正、完成练习）；“收藏数”可作为页内快捷入口，不要单独占一整行。
- 明确指标时间范围：“历史累计”与“近7/30/90天”不能混同；正确率分母遵循现有实际统计口径，不能自行重新计算。
- 记录列表呈现状态（进行中/已完成等）、开始日期、真实完成进度与“继续”操作。没有保存数时不要推测完成率。
- 列表紧凑、对齐、状态颜色一致；大屏避免无意义大留白。

### 5.7 个人中心与学习工作台（截图：4个 tabs）

- 保留学习总览、复习助手、资料与偏好、账户安全四个 tab（如果现有路由和权限依赖这些标签，保持对应功能）。
- 学习总览：把两个过大的空进度圆环改为紧凑的双目标卡/进度条；将“开始今日练习”放在明确 CTA 区。最近7/30/90天切换照旧。
- 数据统计：明确“当前区间 vs 历史累计”，不能出现让用户误解的无上下文 0%。无数据时提示“当前区间暂无有效作答”，但保留真实历史累计。
- 复习助手：最近练习记录与错题优先复习突出操作，并适度压缩空白。
- 资料与偏好：个人资料表单设最大宽度 720px，头像选择与输入表单分组；同步状态保留原实现。
- 账户安全：密码 / 登录会话 / 其他安全设置分组。与学习统计有关的维护操作移至学习数据维护区域（若改变位置可能影响权限/路由，先保留功能并提供原入口跳转）。

### 5.8 管理后台（截图：系统配置/用户管理/管理员账号/我的账户）

- 管理端与学习端保持同一视觉 token，但使用独立导航结构：用户管理、管理员账号、系统配置、数据维护、我的账户（只显示现有权限允许的项目）。
- 现有系统配置左侧二级菜单（LLM接口、邮件服务、用户额度、成本与预算、参考约定）保留分组；内容表单 max-width 920px。
- 系统配置按“连接地址、鉴权、模型参数、运行限制”分段；`API Key` 遮蔽，绝不能通过前端 state、错误日志或埋点泄露，留空保持旧密钥的语义必须保留。保存与测试连接操作成组排列。
- 用户管理表格允许查找与筛选；操作列以主次区分，封禁/会员调整/重置密码触发已有确认策略；无权限的按钮不可见或不可操作，权限由服务端最终校验。
- 管理员账号：新建表单从四列横排调整为合适的两列/单列，创建按钮居右；管理列表的“重置口令”“删除”使用清晰危险操作提示。
- 我的账户：密码修改与账户管理；把“更新考点映射”等数据维护功能转至数据维护板块，在原位置可保留入口而非删功能。
- 不得公开管理员入口给普通用户，也不得使前端权限显示代替服务端鉴权。

### 5.9 实际答题页（用户未提供截图）

必须先检查仓库现有答题页再调整；不得根据想象重做交互。若确有相应页面，建议采用：顶部进度/计时，中间阅读与选项，右侧答题卡（桌面）/底部抽屉（移动端），固定“上一题/下一题/提交”操作区；普通练习解析按原语义，模拟考试不得提前泄露答案。所有保存、计时、答题状态、草稿规则保持不变。

## 6. 响应式行为

- >=1440px：侧栏 224px，真题卡片三列，内容容器最大 1360px。
- 1024–1439px：侧栏可折叠，真题可两列或三列（按可用宽度决定）。
- 768–1023px：默认折叠侧栏，滤镜字段优先换行，表格必要时使用局部横向滚动。
- <=767px：学习端底部核心导航或顶部抽屉导航，主内容单列；筛选器改抽屉；答题卡使用抽屉；避免固定宽度卡片溢出。
- <=390px：确保 320–390px 常见窄屏不出现水平整体滚动，所有表单可触达；目标点击区域建议 >=44px。

## 7. 状态、可访问性与可靠性

- 每个列表和表单必须有 loading、empty、error、success 的合理处理；不要用永远旋转的 loading 掩盖失败。
- 色彩对比尽量符合 WCAG 2.2 AA（普通文本至少 4.5:1；非文字控件边界、焦点等至少 3:1 的适用条件）；不能只靠颜色区分“已订正/待订正”。
- 键盘 Tab 顺序合理，focus-visible 清晰，搜索型下拉能够通过键盘操作；弹窗开关与焦点恢复正确。
- 危险动作与保存设置按既有服务端行为处理；如需 optimistic UI，失败时必须回滚并提示。
- 页面不得有整体横向溢出、叠层覆盖重要按钮、重复双滚动条、横向拥挤输入框或控制台错误。
- URL、筛选、分页和当前 Tab 状态尽量支持浏览器前进后退；不得使未保存表单因装饰性路由切换丢失。
- 不额外加载大型图像和动画资源；按需加载并控制新增依赖。

## 8. 严禁的做法

- 只替换颜色变量、只改几个 margin 就宣称完成。
- 把每页做成同一种高卡片模板；用大量无意义的大标题占首屏。
- 为了好看而隐藏原本重要的筛选条件或业务操作。
- 将真实统计数字改成截图常量，或用假的图表代替真实数据。
- 大范围更换技术栈、重建数据库、修改后端合同或默认路由。
- 明文打印 API Key、Cookie、密码、用户私密信息。
- 引入“全站字体极小”“所有内容都变成大面积卡片”“大量 hover 动画”等过度设计。
- 在没有证据的情况下改动考试类别或原始数据的业务含义；需要拆分显示时必须保留正确映射。

## 9. 实施顺序与验收

### Phase A：基础设施与公共组件
1. 扫描并形成页面-组件对照和风险点。
2. 建立 token、全局基础排版、侧栏和顶栏。
3. 抽象共用卡片、搜索器、按钮、状态、分页、菜单、弹层。
4. 确保所有现有路由仍可访问；先运行构建/测试。

### Phase B：核心页面
1. 题库练习：筛选器、题目列表、批量练习入口。
2. 真题试卷：卡片与地区筛选器。
3. 错题本/收藏：复用题目行、简化操作。
4. 学习记录：四卡布局和进度状态。
5. 考点地图：双栏层级导航。

### Phase C：个人中心、后台与移动端
1. 学习总览、复习助手、资料偏好、账户安全。
2. 管理后台导航、表单、表格及确认行为。
3. 窄屏与键盘交互修复。

### 验收断点与测试矩阵

- 视口至少：1920x1080、1440x900、1024x768、768x1024、390x844、360x800。
- 每页对比：原版截图、改版截图、主要交互实测。必要时保留截图在本地 `design-review/`（不要放入 git 中含敏感数据的截图）。
- 核心工作流：题库筛选->题目->开始练习->返回，真题筛选->开始/继续，考点->关联题，错题订正/收藏，收藏取消，记录恢复，个人资料保存，修改密码与会话，管理员查询与配置测试（只在安全测试环境运行，不要误改线上）。
- 回归：构建成功；现有测试通过；新增或变更组件的测试通过；无明显控制台报错；无大面积空白和元素重叠。
- 若无法运行受认证保护的测试，说明未验证项目并提供本地复现步骤，不得虚称通过。
